# 디자인 프롬프트 (claude.ai/design 용)

와이어프레임과 비주얼을 따로 나누지 않고, 산출물 순서만 단계로 나눈다.
흐름이 흔들리는 화면은 참가자 입력과 공개 연출 둘뿐이라 그 둘만 로파이로 먼저 본다.

```
[제품]
"오늘 커피 누가 쏠까" - 팀에서 커피 쏠 사람을 운세로 정하는 모바일 웹 게임.
참가자 이름을 넣고 캐릭터를 고르면, 카드를 한 장씩 뒤집으며 운세 점수를 공개하고,
운세가 제일 좋은 사람이 "오늘 베푸는 사람"으로 당첨된다.
당첨은 벌칙이 아니라 축하다. 결과는 링크와 이미지 카드로 공유한다.

[사용 환경]
- 모바일 전용. 기준 폭 390px, 세로 모드만.
- 점심 먹고 서서 쓰는 상황. 한 손, 엄지 범위 안에 주요 버튼.
- 로그인 없음, 설정 없음. 첫 화면에서 30초 안에 결과까지 가야 한다.

[무드]
- 게임형. 동적이고 발랄하고 약간 뻔뻔한 느낌. 가챠 뽑기나 아케이드 결과 화면의 들뜸.
- 운세지만 점집 느낌은 금지. 사주 톤이 아니라 "오늘의 뽑기" 톤.
- 참고 결: 닌텐도 파티 게임 UI, 뽑기 캡슐 머신, 편의점 이벤트 스티커.
- 피할 것: 보라색 그라데이션, 글래스모피즘, 기본 SaaS 느낌의 회색 카드, 얇은 선 아이콘.

[색과 타이포]
- 바탕은 밝은 크림이나 따뜻한 베이지. 커피 연상.
- 포인트 색 2개를 강하게. 하나는 당첨 연출용(금색 또는 주황), 하나는 액션 버튼용.
- 운세 등급 4단계(대길, 길, 평, 흉)마다 고유 색과 스티커 느낌의 라벨.
- 제목은 두껍고 둥근 한글 산세리프. 숫자(점수)는 크고 과장되게.
- 본문은 짧은 문장이 대부분이라 가독성보다 리듬감 우선.

[모션 원칙]
- 모든 화면 전환에 탄성이 있다. 카드가 뒤집힐 때 살짝 튀고, 점수는 숫자가 굴러 올라간다.
- 공개 연출은 긴장 → 터짐의 구조. 마지막 카드 전에 한 박자 쉬고, 당첨 순간에만 컨페티.
- 기본 상태에서도 캐릭터가 미세하게 숨쉬듯 움직인다.
- 과한 건 금지. 연출은 당첨 순간 한 번, 나머지는 손맛 수준.

[화면 6개]
1. 랜딩: 한 줄 카피 + 시작 버튼. 지난 참가자 불러오기 보조 버튼.
2. 참가자 입력: 이름 칩 추가, 칩마다 캐릭터 선택. 2명 이상이면 다음 버튼 활성.
3. 규칙 확인: 당첨 규칙 토글(높은 사람 / 낮은 사람), 오늘의 이벤트 규칙 배지(예: 금요일 대길 확률 상승).
4. 공개 연출: 뒤집힌 카드가 참가자 수만큼 깔림. 탭하면 점수 낮은 순으로 한 장씩 공개. 마지막 한 장이 남을 때 긴장 연출.
5. 가위바위보: 동점일 때만. 두 캐릭터 대결 구도.
6. 결과: 당첨자 크게(캐릭터 + 점수 + 대길 메시지), 아래에 전원 등급과 메뉴 추천 리스트(주문표처럼), 공유 버튼 3개(링크 복사, 이미지 저장, 카카오).

[컴포넌트]
- 운세 카드(앞면/뒷면), 등급 스티커 라벨, 점수 카운터, 캐릭터 선택 그리드(8종),
  이름 칩, 큰 액션 버튼, 이벤트 규칙 배지, 결과 공유 카드(1080x1350 이미지용 별도 레이아웃).
- 캐릭터는 나중에 픽셀 캐릭터로 바꿀 수 있으니 자리만 잡고 임시 도형으로.

[산출물 순서]
1. 참가자 입력, 공개 연출 두 화면만 회색 로파이로 먼저. 레이아웃 대안 2개씩.
2. 내가 고르면 무드 방향 A(아케이드 뽑기 느낌), B(편의점 이벤트 스티커 느낌) 시안.
3. 무드 확정 후 디자인 시스템(색, 타이포, 간격, 버튼, 카드, 라벨)과 6화면 전체, 공유 이미지 카드.
```
