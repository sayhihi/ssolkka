# 쏠까 (ssolkka) - 기능과 유저 플로우

"오늘 커피 누가 쏠까". 팀에서 커피 쏠 사람을 운세로 정하는 모바일 웹 게임.
운이 제일 좋은 사람이 "오늘 베푸는 사람"으로 당첨된다. 당첨은 벌칙이 아니라 축하.

## 구성 (Vercel)

- Next.js App Router 한 프로젝트. 화면은 `/`(랜딩), `/play`(참가자 입력, 규칙), `/r`(공개 연출, 가위바위보, 결과).
- 저장소 없음. DB 없음, 로그인 없음. 게임 상태는 URL 쿼리에 전부 담고, 링크를 연 쪽에서 재계산한다.
- 점수는 `버전|날짜|이름` 해시로 결정. 같은 날 같은 이름이면 어디서 열어도 같은 점수. 새로고침 재굴림 불가.
- `lib/fortune.ts`의 `FORTUNE_VERSION`. 계산식이나 규칙을 바꾸면 버전을 올리고 옛 버전은 남긴다(과거 링크 보호).
- localStorage는 지난 참가자 이름 자동 채우기만.
- OG 이미지 라우트 `/api/og`(예정). 결과 링크 미리보기 카드를 요청 시점에 그린다. 유일한 서버 코드.
- 배포: GitHub main 푸시 = Vercel 자동 배포. 도메인은 기본 vercel.app.

## URL에 담기는 것 (`lib/game-url.ts`)

| 키 | 뜻 |
|---|---|
| v | 계산 로직 버전 |
| d | 날짜 YYYY-MM-DD (KST) |
| p | 참가자 이름, 쉼표 구분 |
| c | 캐릭터 번호, 쉼표 구분 |
| r | 당첨 규칙 high(높은 사람) / low(낮은 사람) |
| e | 요일 이벤트 적용 1/0 |
| t | 동점 시 가위바위보 승자 index (있을 때만) |

점수와 당첨자는 넣지 않는다. 링크 연 쪽에서 다시 계산하니까 위조할 수 없다.

## 주요 기능

### 게임 설정
- 참가자 2~10명, 이름 중복 방지.
- 참가자별 캐릭터 선택. v1은 고정 8종(임시 이모지), 픽셀 캐릭터 생성은 v2.
- 당첨 규칙: 기본 "점수 제일 높은 사람이 쏜다", 옵션 "제일 낮은 사람".
- 요일 이벤트(v1): 월요일 전원 -5, 금요일 전원 +8. 설정에서 끌 수 있다.

### 운세
- 점수 0~100, 등급 4단계: 대길(85+), 길(60+), 평(30+), 흉.
- 등급별 메시지 풀. 대길은 전부 "베푸는 날" 톤. `{name}`, `{day}` 템플릿 변수. 등급당 30개 이상 목표(지금은 씨앗 5개).
- 메뉴 운세: 등급에 따라 오늘 마실 음료 한 줄. 결과 화면이 주문표가 된다.
- 동점: 당첨 후보끼리 실제 가위바위보, 이긴 사람을 눌러 확정(URL `t`).

### 공개 연출
- 카드 뒤집기. 점수 낮은 사람부터 한 명씩, 당첨 후보가 마지막.
- 탭해서 다음 카드. 자동 재생 옵션(예정).
- 마지막 카드에서 당첨 연출 한 번(컨페티, 예정).

### 결과와 공유
- 당첨자 크게, 전원 등급과 메뉴 추천 리스트.
- 결과 링크 복사. 이미지 저장, 카카오 공유(예정).
- 링크 미리보기 카드 (OG, 예정).
- 결과 링크를 연 사람은 "다시 보기"로 공개 연출 재생, "우리도 해보기"로 새 게임.

### v2 후보
- 링크 참여 모드(각자 폰에서 자기 카드, 실시간 동기화. 이때 방 ID와 서버 저장이 생김).
- 면제권, 역전 카드. 지난 당첨자 보호 토글.
- 픽셀 캐릭터 생성 연동.
- 슬랙 봇(`/coffee`, 이모지 참가, 봇이 결과 공개).
- 커피 장부(결과 링크 모아 집계하는 페이지).

## 유저 플로우

### 진행자 (한 폰 모드)
1. 랜딩: 한 줄 카피 + 시작. 지난 참가자가 있으면 자동으로 채워짐.
2. 참가자 입력: 이름 추가, 캐릭터 선택. 2명 이상이면 다음.
3. 규칙 확인: 당첨 규칙, 요일 이벤트 토글.
4. 공개 연출: 카드가 뒤집힌 채 깔리고, 탭마다 점수 낮은 순으로 공개.
5. 동점이면 가위바위보 화면.
6. 결과: 당첨자, 전원 등급, 메뉴. 공유 버튼.
7. 다시 하기는 참가자 입력으로. 같은 날 같은 참가자면 같은 결과라는 안내.

### 공유 링크를 받은 사람
1. 카톡/슬랙에서 미리보기 카드 보고 링크 열기.
2. 공개 연출부터 재생(링크에 결과가 없으니 재계산). 당첨자와 자기 등급, 메뉴 확인.
3. "우리도 해보기"로 새 게임. 여기서 퍼진다.

## 과거 결과는 어디서 보나
- 공유한 채팅방의 링크가 기록.
- 날짜와 이름만 알면 재계산으로 복원 가능(그래서 버전 번호가 필수).
- 누적 집계가 필요해지는 시점이 DB를 붙일 시점.

## 애니메이션 스택
- Motion(옛 framer-motion): 카드 뒤집기, 화면 전환, 칩 추가/삭제, 스프링.
- canvas-confetti: 당첨 순간.
- use-sound: 카드 소리, 당첨 효과음. 모바일은 첫 터치 후 재생되므로 시작 버튼에서 오디오 해제.
- 캐릭터 숨쉬기 같은 상시 모션은 CSS keyframes.
- 공개 연출 타임라인이 복잡해지면 그 부분만 GSAP 검토.
